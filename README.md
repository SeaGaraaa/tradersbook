# Trader'sBook (PWA)

Приложение для Windows и iPhone поверх Google-таблицы журнала. Данные остаются в таблице
`Journal`, программа `tools/journal_sync/sync.py` работает как раньше.

- Журнал: таблица на компьютере, карточки на телефоне; фильтры по паре, результату, месяцу, поиск.
- Карточка сделки: все 20 колонок, POI и Entry — кнопками. Списки POI и Entry правятся прямо в карточке
  («Изменить список») и хранятся на листе `Lists` (создаётся при первой правке; до этого берутся с Dashboard).
  При правке Entry обновляется и выпадающий список в колонке G журнала. Скриншоты по таймфреймам:
  ссылка TradingView, фото с телефона или Ctrl+V картинки. Фото загружаются в Google Drive (папка
  «Trading Journal»), в таблицу пишется ссылка.
- Бэктест: переключатель «Реальный счёт / Бэктест» вверху. Сделки бэктеста — на листе `Backtest`
  (создаётся при первой сделке; колонки как в Journal + U «Idea»). Идея обязательна, список идей —
  в карточке («Изменить список»), хранится в колонке C листа `Lists`. Dashboard бэктеста: таблица
  «Сравнение идей» (Trades, WinRate, Expectancy R, Σ R, PF, AVG RR, Profit, Max DD; сортировка по
  Expectancy; пометка «мало данных» при < 30 сделках) и статистика выбранной идеи. Синхронизация с MT5
  лист Backtest не трогает. Статистика бэктеста (Dashboard, Stats) — всегда по одной идее: выбранной
  в таблице сравнения, по умолчанию лучшей.
- Скриншоты: список таймфреймов правится в карточке («Изменить список» у блока «Скриншоты»), хранится
  в колонке E листа `Lists`. W1–m3 пишутся в колонки L–R, другие таймфреймы — в колонку U «Screens»
  строками `TF: ссылка ссылка` (в Backtest Idea — колонка V). Сортировка строк — по всем колонкам.
- Чек-лист: отдельная вкладка «Чек-лист» — пройти перед торговлей. Выбор актива и сетапа, ✓ / ✗ по пунктам,
  вердикт «Можно торговать» / «Сделки нет». Каждый сохранённый — строка на листе `Checklists` (создаётся сам):
  время, пара, сетап, вердикт, коды «да» / «нет», тексты невыполненных, заметка. Ниже — сводка и история по дням.
  Шаблон правится там же («Изменить чек-лист»), хранится JSON-ом в `Lists!F2` (у каждого пользователя — в его
  таблице); по умолчанию — как `checklist.md`. Выгрузка в PNG и PDF (`js/export.js`: рисунок на canvas,
  PDF — листы A4 из JPEG без внешних библиотек; пустой чек-лист выгружается как бланк для печати).- Стратегия: вкладка «Стратегия» — правила пользователя на листе `Strategy` его таблицы (Markdown: `#`/`##`,
  списки, `- [ ]`, `**жирный**`, `:::callout ⚠️ … :::`, `:::details Открыть … :::`, картинки). У нового пользователя
  листа нет — вкладка предлагает начать с шаблона. Картинки — в Google Drive; `![](img:имя)` — ещё не загружена,
  кнопка «Загрузить картинки» подставляет файлы по имени. Модуль `js/strategy.js`.
- Пары: свой список в карточке («Изменить список»), общий для обоих режимов, колонка D листа `Lists`.
- Dashboard и Stats считаются теми же формулами, что в таблице (проверено: 43 показателя совпали).
- В таблицу пишутся только изменённые ячейки; перед записью проверяется, что в строке та же сделка.
  Новая сделка дописывается и журнал сортируется по времени входа.

## Пользователи и данные

- У каждого пользователя своя таблица. При входе приложение ищет её так: таблица, открытая на этом устройстве
  раньше → таблица владельца из `config.js` (`spreadsheetId`, откроется только у того, у кого есть доступ) →
  таблица приложения в Drive пользователя (метка `appProperties.tradersbook = 1`) → иначе создаёт новую
  «Trader'sBook» (листы Journal и Lists, остальные — по мере надобности) в папке «Trading Journal».
- Новая таблица пустая: пары, POI, Entry, идеи, таймфреймы, чек-лист и стратегия пользователь заполняет сам.
  Стартовый чек-лист — общий (`GENERIC` в `js/checklist.js`), стратегия — пустая с шаблоном.
- При выходе с устройства стираются токен, id таблицы, черновики и папка Drive (`tj.*` пользователя).
- Сессия считается по времени устройства, переведённому в лондонское: Азия 00–07, Франкфурт 07–08,
  Лондон 08–13, Нью-Йорк 13–24 (для Бухареста это 02–09, 09–10, 10–15, 15–02).
- Пока OAuth-приложение в Google Cloud в режиме Testing, войти могут только адреса из «Audience → Test users»
  (до 100). Для всех — опубликовать приложение (Google покажет предупреждение «не проверено», доступ к таблицам —
  чувствительная область, для снятия предупреждения нужна проверка Google).

## Файлы

- `index.html`, `styles.css`, `js/` — приложение (без сборки, обычные JS-модули).
- `config.js` — Client ID и ID таблицы (секретов нет).
- `sw.js`, `manifest.webmanifest`, `icons/` — установка на рабочий стол / экран «Домой».
- `serve.bat` — локальный запуск на http://localhost:8080.
- `make_icons.py` — перерисовать иконки.

## Настройка входа через Google (один раз)

Google Cloud Console → проект `trading-511922`:

1. «APIs & Services → Library»: включить **Google Sheets API** и **Google Drive API**.
2. «Google Auth Platform» (OAuth consent screen): тип **External**, имя «Trader'sBook»,
   в «Audience → Test users» добавить свой Gmail. Статус оставить **Testing**.
3. «Clients → Create client» → **Web application**:
   - Authorized JavaScript origins: `http://localhost:8080` (и потом адрес хостинга);
   - Authorized redirect URIs: `http://localhost:8080/` (и потом адрес хостинга со `/` на конце).
4. Client ID вписать в `config.js` → `clientId`.

При входе Google покажет «Приложение не проверено» — это нормально для личного приложения
в режиме Testing: «Дополнительно → Перейти». Отметить доступ к таблицам и к файлам Drive.
Вход действует 1 час, потом приложение попросит войти снова (несохранённая карточка восстановится).

## Установка

- Windows (Edge/Chrome): открыть адрес приложения → значок «Установить» в адресной строке.
- iPhone (Safari): открыть адрес → «Поделиться» → «На экран Домой».
